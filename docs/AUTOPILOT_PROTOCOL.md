# GLOBAL LAW — AUTOPILOT PROTOCOL

## Purpose

The future AUTOPILOT allows the project to progress through the roadmap through a simple user instruction such as:

> CONTINUE

Autopilot is not permission to guess. It is permission to execute the next safe, defined research or build step.

## Operating loop

1. Read the current roadmap and repository state.
2. Identify the highest-priority unfinished task.
3. Check dependencies and Investigation Gates.
4. Research authoritative sources where external research is required.
5. Build or update the smallest useful verified unit.
6. Validate schemas and relationships.
7. Record provenance.
8. Run quality checks.
9. Commit the completed work.
10. Report exactly what changed.
11. Identify the next eligible task.

## Stop conditions

Autopilot must stop rather than improvise when:
- the required source cannot be verified;
- authority is ambiguous;
- legal interpretations materially conflict;
- a copyright/licensing question is unresolved;
- the data model would need an architectural change;
- a task requires a human/legal decision;
- the next action could materially misstate law;
- credentials, private data or unauthorized access would be required.

## Never do automatically

- invent legal text;
- invent citations;
- mark unverified law as verified;
- silently change historical law;
- claim legal equivalence without evidence;
- present AI output as authoritative law;
- bypass review gates;
- expose private user information.

## CONTINUE command

When the user says CONTINUE, resume from the highest-priority safe task in the master roadmap. Do not restart the project or choose an arbitrary task.

## Progress report

Every cycle should state:
- task completed;
- files/data changed;
- evidence status;
- verification status;
- unresolved issues;
- commit/result;
- next recommended task.

## Long-term principle

Autopilot increases execution speed.

It never lowers the project's accuracy standard.
